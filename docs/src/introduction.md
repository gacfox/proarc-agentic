# 简介

ProArc Agentic 是一个基于 Spring Boot 的大语言模型（LLM）智能体开发框架，来源于一系列企业级项目的实践沉淀。它以 Spring Boot Starter 的形式提供，引入依赖后即可在工程中快速构建 LLM 对话、工具调用与 ReAct 智能体应用。

在企业级项目中接入大模型时，我们通常会遇到这几类问题：不同服务商的 API 大多兼容 OpenAI 规范但细节各异，异常处理散落在各处难以统一；工具调用需要手写大量 JSON Schema；智能体循环的编排逻辑与业务代码耦合严重。ProArc Agentic 正是围绕这些问题设计的，它不试图覆盖所有模型服务商的私有协议，而是专注于 OpenAI 兼容端点这一事实标准，把客户端、工具、智能体循环这几块地基打牢。

## 核心能力

框架的能力可以划分为四个层次，如下图所示。

```
┌─────────────────────────────────────────────┐
│  ReAct 智能体（ReActAgentExecutor）           │
│  结构化输出（StructuredExecutor）             │
├─────────────────────────────────────────────┤
│  工具注册（ToolRegistry / @AgenticTool）      │
│  提示词模板（PromptTemplate）                 │
├─────────────────────────────────────────────┤
│  LLM 客户端（LlmClient / OpenAiLlmClient）    │
│  拦截器链（重试 / 限流 / 动态 Header）        │
├─────────────────────────────────────────────┤
│  连接池（llmHttpClient，reactor-netty）       │
└─────────────────────────────────────────────┘
```

最底层是由 Starter 自动装配的 reactor-netty 连接池 `llmHttpClient`，为所有 LLM 请求提供统一的连接管理。往上是 `LlmClient` 客户端层，负责面向 OpenAI 兼容端点的阻塞与流式调用，并外挂了拦截器链来处理重试、限流这类横切逻辑。再往上是工具注册与提示词模板，工具通过注解声明，框架自动生成 JSON Schema 并注册到全局注册中心。最顶层是 `ReActAgentExecutor` 智能体执行器和 `StructuredExecutor` 结构化输出执行器，它们把底层能力编排成可直接解决业务问题的形态。

## 设计约定

在深入各个章节之前，有几个贯穿全框架的约定值得先了解。

**OpenAI 兼容端点是唯一的通信协议。** 框架内置的 `OpenAiLlmClient` 面向所有兼容 OpenAI Chat Completions 规范的端点，无论是 OpenAI 官方、国内的兼容服务（如阿里 DashScope 的兼容模式），还是 vLLM 等自部署推理框架，都可以直接接入。

**阻塞调用建立在流式之上。** `OpenAiLlmClient` 的阻塞式调用内部实际上是发起流式请求并聚合所有分片的结果。这样做的好处是两种调用方式的行为完全一致，拦截器、异常处理只需要针对一套链路实现，同时也避免了长文本生成时阻塞请求容易超时的问题。

**一切皆可拦截。** 客户端层的 `LlmInterceptor` 和智能体层的 `AgentInterceptor` 都采用环绕式拦截器链设计，重试、限流、审计、人工介入等逻辑都通过拦截器挂载，而不是硬编码在主流程里。

**异常带有明确的语义。** 框架将 LLM 调用中可能出现的问题统一映射为 `LlmException` 体系，每种异常都标注了是否可重试（`retryable`），重试拦截器正是依据这个标记工作的。
